🗺️ How this guide works

⏱ 10 min to read and try

Hi 👋 You don't need to learn all of this.

This page looks long, but it's really a menu. Six lessons are marked Essential, and those six are enough to publish your critical report as a website. Everything else is there for when you need it. Each lesson takes 10–40 minutes. Rusty after Unit 2? Start with the 15-minute recap. Open one, try it, tick it off.

Have your midpoint draft ready (about 600 words). Each essential lesson ends with a step where you build your own critical report in Visual Studio Code, so by the end of the six your writing is a working website.

✅ Making mistakes is normal — in fact, it's expected and an essential part of learning. Rik Lomas of SuperHi describes coding as swinging between extremes, feeling "like an idiot or a genius, nothing in between". Beginners and experts share that cycle of frustration and breakthrough. If you feel stuck, take a break, go back a lesson, press Reset and try again. It's usually one tiny typo.

🤔 Why learn web publishing from scratch?

Learning HTML and CSS gives you something templates and online platforms can't: the freedom to let form and content work together. Your critical report, your ideas and their visual presentation shouldn't be separated; they should reinforce each other. Online platforms like Instagram, or website builders like Wix, Squarespace and WordPress, force your content into predetermined formats.

When you understand web publishing fundamentals, you can create the right design for your specific content. Your critical report can be expressed through both your writing and your design decisions, not constrained by someone else's interface.

You're learning to be a designer who shapes the medium to serve your message, not the other way around.

🚑 Stuck? Check these five first

Nine times out of ten, it's one of these. Professionals make them every single day.

  1. Didn't save. VS Code shows a dot on the tab when a file isn't saved. Ctrl/⌘+S, then refresh the browser.
  2. A typo in a name. .pullquote in your CSS and class="pull-quote" in your HTML are strangers to each other.
  3. A missing closing bit. A tag you opened but never closed (</p>), or a missing ; or } in CSS. Everything after it goes strange.
  4. The wrong path. Capitals, spaces or a folder name out of place (Lesson 1).
  5. Messy indenting. It won't break anything, but it hides the mistakes above. Tidy code is easier to fix.

1. A website is a set of files in a folder

2. Your set-up in Visual Studio Code

  1. Make one folder per project and keep everything (HTML, CSS, images) inside it.
  2. In VS Code, go to File → Open Folder. If you see Restricted Mode at the bottom left, click it and choose Trust.
  3. Your first page is always called index.html, all lowercase.
  4. No spaces in file names: use-dashes.css or under_scores.jpg. Treat names as case-sensitive: your laptop may forgive capitals, but many systems don't.
  5. Save (⌘/Ctrl+S), then refresh the browser (⌘/Ctrl+R). Every time.

4. CSS: rules, classes and boxes

  1. Link the stylesheet in the head: <link rel="stylesheet" href="style.css">. One CSS file for all your pages.
  2. A rule is a selector plus declarations: p { background: pink; color: indigo; }. Colon in the middle, semicolon at the end.
  3. A class is a name you give an element, class="fruit", styled with a dot: .fruit { … }.
  4. Everything is a box. Give it a temporary background colour to see it.
  5. You met color, background, width/height, font-family/font-size, margin, padding, border, units (px, %, vw, vh) and position.

5. Images for the web

Keep each image under 1 MB, and export it at twice the size it appears on screen: set to width: 500px in CSS means exported 1000px wide. In Photoshop: File → Export → Save for Web (Legacy), or Export As.

6. When something breaks

  1. Right-click → Inspect → Console. Read any red error messages.
  2. Spelling: mango.jpg isn't mangoes.jpg, and .jpg isn't .png.
  3. Moved files: an image in a folder needs the folder in its path, images/mango.jpg.
  4. Open brackets: every <, { and " needs its partner. VS Code underlines these in red.

📚 Help & resources

Where to look things up, fixes for common problems, and the Unit 5 readings.

You don't need to memorise any of this. Good designers who code aren't the ones who know everything. They're the ones who know where to look.

🚑 When you're stuck

  1. Check the five usual suspects: saving, typos, missing closing bits, paths, messy indenting.
  2. Inspect it. Right-click → Inspect to see what the browser actually reads.
  3. Look it up on W3Schools, try their example, then change it to match what you want.
  4. Still confused? Read MDN for the "why" behind it.
  5. Change one thing at a time, and check your HTML in the validator.
  6. Ask a person: a peer, a technician, a tutor. Or ask AI, with intention.

It worked yesterday…

My images show in VS Code's preview but not in the browser

Check the path letter by letter: the folder name, the file name and the extension (.jpg, .jpeg and .png are all different).

My font has changed to Times New Roman

The browser can't find your font. If you use Google Fonts, check the <link> is in the <head> of this page and the name matches your CSS exactly. If you use a font file, check the path in @font-face (Lesson 10).

The layout is broken on a smaller screen

Look for fixed widths in pixels (width: 1200px) and position: absolute. Swap them for max-width, grid and a media query (Lesson 12).

A style isn't working and I can't see why

Start where Unit 2 taught you: right-click → Inspect, and check the Console for red errors. Then find the element and look at the Styles panel: a crossed-out rule means something more specific won (Lesson 8). Also check for a missing ; or } just above.

🧠 Using AI in web design

⏱ 5 min to read

If you prefer to use AI, use it to assist your learning, not to replace it.

AI tools like ChatGPT can be extremely helpful when you're coding a website. They can generate snippets of HTML and CSS or help you troubleshoot. Think of AI as a creative tool: it can assist in the making, but it doesn't replace your thinking. AI doesn't understand your ideas, your audience, or the message you want to convey. It can't make creative, personal decisions for you.

That's why it's important to learn the fundamentals of HTML and CSS first. With a solid foundation, you can use AI purposefully: critiquing its suggestions, adapting its output, and making sure your creative voice stays central.

🌍 Environmental impact

AI can feel invisible, but it runs on physical infrastructure: huge data centres that use electricity, and water to stay cool. Every time you ask an AI tool a question, you're using computing power that comes with an environmental cost. A short text prompt may use about as much energy as a web search, but longer answers, image generation and "reasoning" modes can use many times more, and these requests add up quickly across millions of users.

This doesn't mean you shouldn't use AI, but it's a good reason to use it with intention: when it supports your learning or helps you solve a specific challenge, rather than out of habit or convenience. Sustainable digital practice starts with awareness.

✓ Assists your learning

"Explain what grid-template-columns does, in simple words." (then check it on W3Schools)
"Why does this CSS rule not apply?" (paste your code, then check the answer in developer tools)
"Give me a small exercise to practise flexbox." (then do it yourself)

✗ Replaces your learning

"Build my critical report website." The result won't be yours, you won't be able to explain your choices, and AI often suggests outdated code or JavaScript you don't need. A good test: could you rebuild it without the AI?

Your project folder

You'll make: a project folder that works on any laptop, online or off

Let's start with the least glamorous lesson, because it saves the most tears. Most “my site is broken” moments turn out to be “my file is in the wrong place” moments.

From Unit 2

Same rule as Unit 2: one folder, everything inside it, index.html in lowercase, and no spaces in names. The difference is that in Unit 5 this folder is the finished site you show at Open Studio.

✓ Works everywhere 
<img src="images/dazzle-ship.jpg" alt="…">
✗ Breaks when the folder moves or on another laptop 
<img src="image/dazzle-ship.png" alt="…">
<img src="/images/dazzle-ship.jpg" alt="…">
<img src="C:\Users\me\Desktop\pic.jpg" alt="…">

Each of these points somewhere the file isn't: the wrong folder name and file type, a / that sends the browser to the top of your hard drive, and a path that only exists on one computer. Also name every file in lowercase with hyphens (dazzle-ship.jpg). Your laptop may forgive capital letters, but many other systems won't.

The page skeleton

You'll make: a starter file for your critical report

You did this in Unit 2, so treat it as a warm-up. Every page has two halves: the <head> is information about the page, and nobody sees it. The <body> is everything the reader sees.

From Unit 2

Your Unit 2 pages started with <!doctype html>, <html>, <head> and <body>. That's still the base. Here you add four lines that make it work for readers: language, characters, phones and a title.

What each line in the head does

LineWhy it matters
<html lang="en-GB">Tells browsers and screen readers the language. Needed for correct hyphenation and pronunciation.
<meta charset="UTF-8">Curly quotes, accents and dashes (’ é —) show properly instead of as Ã©.
<meta name="viewport" …>Without it, phones shrink your page to a tiny desktop view.
<title>The text in the browser tab and in bookmarks. Use your report's title.
<link rel="stylesheet">Connects your style.css file.

Here's a complete starter file. Copy it into a new index.html in VS Code. (Tip: in VS Code, type ! and press Tab to get most of this for free.)

<!DOCTYPE html>
<html lang="en-GB">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Your report title — Your name</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

  <!-- your writing goes here -->

</body>
</html>
Comments are your friend

<!-- like this --> in HTML and /* like this */ in CSS. The browser ignores them. Use them to label sections and leave notes for yourself.

Structuring your writing

You'll make: your first chapter, properly marked up

The shape of a document

You'll make: the outline of your whole page

Now zoom out from sentences to the whole page. A handful of tags name the big regions, a bit like the cover, contents, chapters and colophon of a book.

ElementHoldsHow many
<header>Title, subtitle, your nameUsually 1 at the top
<nav>Your table of contents or menu1 or 2
<main>The main content of the pageExactly 1
<article>A complete piece of writing that could stand alone1 for a report
<section>A chapter or themed group, usually with a headingAs many as you need
<aside>Related but secondary content: margin notes, a glossaryAny
<footer>Credits, colophon, dateUsually 1
<div> / <span>Nothing in particular, just a hook for stylingOnly when nothing above fits
Not sure which tag? Ask yourself…
  • Is it the title of the page? → <h1>
  • Is it a chapter or section heading? → <h2>, <h3>
  • Is it the top of the page, with title and name? → wrap it in <header>
  • Is it a set of links to move around? → <nav>
  • Is it the main content? → <main>, with your report in an <article>
  • Is it a distinct chapter with its own heading? → <section>
  • Is it a side note or something related? → <aside>
  • Is it your reference list? → a <section> at the end of your article (Lesson 7)
  • Is it credits or a date at the very end? → <footer>
  • Is it regular text? → <p>. A list? → <ul> or <ol>

  body { font-size: 11pt; line-height: 1.4; color: black; background: none; }

  h2 { break-before: page; }             /* each chapter on a new page */
  h2, h3 { break-after: avoid; }         /* no heading alone at the bottom */
  figure, blockquote { break-inside: avoid; }
  p { orphans: 3; widows: 3; }           /* no single lines left behind */

  a[href^="http"]::after {               /* show web addresses on paper */
    content: " (" attr(href) ")";
    font-size: 0.8em;
  }
}

@page {
  size: A4;
  margin: 20mm 18mm 25mm;
  @bottom-center { content: counter(page); }   /* page numbers */
}
@page :first {
  @bottom-center { content: none; }            /* none on the cover */
}
Which browser?

Use Chrome or Edge to make your PDF. They understand size and the page-number boxes (@bottom-center). Safari and Firefox still print, but ignore some of these settings.

Save it as a PDF

  1. Open your index.html in Chrome and press Ctrl/⌘+P.
  2. Destination: Save as PDF.
  3. Open More settings. Untick Headers and footers, or the browser adds its own date and web address. Tick Background graphics if you use background colours.
  4. Check the preview, then save.
  5. Test it: open the PDF and try to select a sentence. If you can, it's machine-readable, which is what Turnitin needs.

Level 2: make it a book with Paged.js

Paged.js is a free, open-source tool used by designers and publishers. It turns your long page into real pages in the browser, so you can design spreads, running heads and a contents list with page numbers, then save the PDF.

☝️ About the "no JavaScript" rule

Paged.js is a script, but you don't write any JavaScript: you add one line to a copy of your page used only for print. Your website, index.html, stays HTML and CSS.

  1. Install Live Server. In VS Code, open Extensions, search for Live Server and install it. Paged.js only works when your page is served, not when you double-click the file.
  2. Make a print copy. When your text is final, duplicate index.html and call it print.html.
  3. Add the script to the <head> of print.html, after your stylesheet:
    <script src="https://unpkg.com/pagedjs@0.4.3/dist/paged.polyfill.js"></script>
  4. Open it with Live Server: right-click print.html → Open with Live Server. Your report appears as a column of pages.
  5. Design the pages with the CSS below. Put it in a new file, print.css, and link it in print.html only, under your style.css link. Then save as PDF as in Level 1. Set Margins to None: Paged.js already applies yours.
@page {
  size: A5;
  margin: 22mm 16mm;
}

/* Page numbers on the outside edge */
@page :left  { @bottom-left  { content: counter(page); } }
@page :right { @bottom-right { content: counter(page); } }

/* Running head: the current chapter title, top right */
h2 { string-set: chapter content(text); break-before: right; }
@page :right { @top-right { content: string(chapter); } }

/* Page numbers in your contents list */
nav a::after {
  content: " " target-counter(attr(href), page);
  float: right;
}
